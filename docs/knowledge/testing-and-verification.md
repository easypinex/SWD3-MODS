# 測試與驗證

## 證據標記

所有研究與跨專案規則使用以下標記：

- **已實測**：列出版本、步驟與可觀察結果。
- **已靜態反解**：列出遊戲／工具版本、來源雜湊、分析方法與可定位的控制流；只證明被分析版本的程式碼事實，不代替 runtime 安全性。
- **官方檔內說明**：保留來源檔名，不推定所有 runtime 行為。
- **專案決策**：說明安全或 UX 選擇，不描述成引擎能力。
- **待驗證**：不得成為正式功能必要依賴。
- **已否決路徑**：只對實驗條件下的方案下結論。

研究狀態（持續使用、進行中、已歸檔）與上述證據類型分開。mock、語法與封裝成功必須明列驗證層次，不能標成遊戲行為已實測。單次未觀察到事件只否決所列條件，不提升為全引擎不存在。

發生矛盾時，比對版本、案例、操作、結果與原始來源；較晚的籠統「已完成」只作產品狀態紀錄，不能覆蓋缺少步驟／結果的通用驗收。保留舊敘述作帶日期的歷史，並在現行入口標出已取代或仍待核對。

### 結論到證據的定位

通用結論旁直接連到支持它的研究／TESTING **章節或案例錨點**；只連研究清冊、整個專案 README 或另一份通用摘要，不算完成證據定位。短段落可共用一個來源連結，無須另建重複的證據總表。

| 結論種類 | 來源必須能定位的內容 | 適用條件與缺口 |
| --- | --- | --- |
| 已實測 | 遊戲／MOD 版本、操作、實際結果；有保存時直接連 Console、截圖或 trace 案例。 | 註明戰場、角色、輸入／選單等影響結論的條件。只有文字摘要時明列，不能稱為完整原始 log。 |
| 已靜態反解 | 來源指紋、分析方法／腳本、函式位址或控制流段落。 | 位址限所列雜湊；名稱存在、可達性與 runtime 安全分開判讀。 |
| 官方檔內說明 | 原版基線、檔名及函式／欄位／可搜尋的 symbol。 | 原版檔案由正版安裝重建時，連到基線與重建入口，不依賴未提交的本機副本連結。 |
| 專案決策、mock 或待驗證 | 專案契約、實作 symbol、mock 案例或待測矩陣。 | 不以程式存在、mock 通過或驗收步驟取代實機結果。 |

來源缺少精確版號、日期或完整操作時，寫「原紀錄未保留」及仍可採用的範圍；不可用整理日期、現行 metadata 或相鄰案例的版本替它補值。「未發現 API」必須限定盤點版本與路徑，不寫成所有版本均不存在。

### 現行版本與歷史結果

持續使用的探針 README 在操作前列出來源 metadata 的版本、可辨識的載入訊息及該版本已完成／待完成的驗證。metadata 只識別來源；實際安裝或訂閱版仍需另核對封包與載入來源，不能由 README 推定。

現行操作只保留一套；舊版本結果保留各自的日期、版本與章節錨點。新版已建置不代表舊案例已在新版回歸，初始化訊息也不代表該版所有 callback 已實際觸發。

## 文件與搬遷檢查

修改文件至少檢查相對檔案連結與章節錨點。移動研究資料時先保存來源／目的映射、檔案數、大小與 SHA-256，再核對搬遷後內容；同步檢查指令路徑、工具快取定位、忽略規則及受影響的既有靜態／mock 測試。這些只證明整理完整性，不構成新實機驗收。

## 自動檢查

依專案風險組合：

- Lua 靜態語法解析。
- 純規則或 mock runtime 測試。
- StringDB key 完整性與重複檢查。
- 暫改資料的保存、還原、重入及錯誤路徑。
- 封裝後反向解包，逐檔 SHA-256 比對。
- `dist`、安裝版與工作坊內容版雜湊比對。

`luaparse`、`fengari-node-cli`、專案包裝器與標準雜湊命令見 [工具與命令參考](tools-and-commands.md)；具體案例保留在各專案 `TESTING.md` 或 README。

## Console 驗證

依[工具與命令參考的本機實機啟動流程](tools-and-commands.md#本機實機啟動流程)先開 Console，再直接啟動 `<game-root>\swd3.exe`。每個正式 MOD 應在 README 列出穩定的初始化或成功訊息；只有遊戲主視窗與 Console 載入訊息都出現，才可記為啟動成功。

Console 原則：

- 記錄初始化、設定變更、重要狀態轉換及錯誤。
- 同一結果只記一次，不逐幀洗版。
- 「MOD 管理顯示啟用」或「檔案存在」不能證明 Lua 已載入。
- 錯誤訊息應足以定位失敗階段，但不要輸出大量遊戲資料。

## 必須實機驗收的項目

執行方式遵守 [AGENTS 的遊戲中人工測試規則](../../AGENTS.md#遊戲中測試由使用者人工操作)；以下案例由使用者操作，Agent 準備步驟並整理回報與日誌證據。

- 鍵盤、滑鼠、控制器的確認、取消及輸入穿透。
- UI 在相關選單、解析度與語言下的位置、截斷與字型。
- 取消、離開選單、換圖、進戰鬥、逃跑和重新開局後的清理。
- 新舊存檔、不同存檔、停用與重新啟用。
- 唯一物品、背包滿載、原生動畫、Steam 統計和成就是否只執行一次。
- 與相關 MOD 的兩種載入順序。

任何資料未還原、重複交易／獎勵、跨存檔污染、UI 殘留或危險穿透都阻斷發布。

## 隔離研究探針

未知 API 或引擎行為先建立最小探針：

1. 一次只驗證一個假設。
2. 使用未綁定的觸發方式，避免與正式 MOD 同時處理同一按鍵。
3. 預設只讀；若必須暫改資料，提供完整還原與停用方法。
4. README 寫明前置狀態、操作、預期結果、失敗時如何停止。
5. 研究文件同時記錄成功、失敗、未測範圍與版本。
6. 只有可重跑且對多專案有效的結果才提升到通用知識庫。

執行檔字串、函式名稱或工具退出碼只能形成研究線索，不能單獨形成「API 可用」結論。
