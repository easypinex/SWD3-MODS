# 原版戰鬥資料：能力上限、敵人強度與收妖

研究日期：2026-09-03；終局資源補充與舊結論校正：2026-09-06。資料版本為本工作區解出的 Steam HD 4.0.5 `script_index.ssmod`。本文件保存原版資料與其可驗證推論；它不直接修改遊戲資料或任何插件規則。文中的「自由挑戰」建議是目前已知的整合案例，不是資料本身的專屬用途。

## 結論先行

1. 四名正式隊員的原版等級上限都是 Lv60；其「只含角色成長」的滿等數值可精確重算。但這不是遊戲的絕對能力上限，因為原版有可在平時使用、增加 HP／MP／SP／力量／耐力／智慧／敏捷等上限的道具。
2. 單隻蚩尤是原版刻意設計的隱藏終局挑戰；五隻蚩尤則是 150,000 HP、每一敵方回合最多五次行動的非原版編制。依可見資料，不應把「五隻」視為與單隻相同等級的公平挑戰。
3. 蚩尤 HP≤15% **仍不能**用原版靈契收服：它同時是 `IT_06` 劇情類、不是 `IT_12` 活物卡，且 Lv80 對 Lv60 的等級差已超過原版允許值。若開放，必須做成僅限自由挑戰的契約規則，並將結果交換為新的活物卡 ID。
4. 現行自由挑戰的 193 個可戰鬥資料中，96 個已有 `IT_12` 活物卡、97 個沒有。不能假設所有可挑戰敵人都能被原版靈契；更不應直接把劇情敵人的範本改成活物卡。

### 為何這不是「絕對最強」

原版物品資料中有 `Calculation=256` 且 `UsePlace=2` 的平時能力上限道具。例如蜂王露 +10 力量、活靈芝 +100 SP、三葉雪桑果 +100 HP、七合龍爪花 +100 HP／MP／SP。它們的物品定義、價格與數值已列在 `generated/permanent-growth-items.csv`；但已解出的 Lua 未能證明商店庫存是否無限、每個存檔可取得份數，或 native engine 的最終能力硬上限。因此：

- 「只用等級成長」的滿等基準：**已可重算**。
- 「正常遊玩可取得的一次性總量」：**待補劇情／商店／掉落來源索引**。
- 「利用可重複購買／煉化後的理論絕對值」：**待驗證 native 上限與庫存**，目前不能宣稱有固定最大值。

## 2. 原版可達成的終局戰術資源

### 裝備與法寶

已解出的數值與攻略交叉一致的終局武器候選為：賽特的軒轅劍 `+590 ATK`、妮可的萬鈞神弩 `+200 ATK`、卡瑪的四極皇霸刀 `+215 ATK`、李靖的憾天神槍 `+248 ATK`。每項的角色限制、加成與特殊能力都在 `generated/equipment-and-artifacts.csv`。

對蚩尤的防禦核心不是單純堆 DEF，而是雷電與暗系防護：

- 雷公鎚：法寶修練後「抵抗敵方雷電系法術 80%」。
- 暗黑魔樽：法寶修練後「抵抗敵方暗系法術 80%」。
- 金鐘罩秘笈：護罩指令消耗 SP；攻略資料記錄修練後為 DEF +70%、最長 6 回合。
- 三教霞光鏡：可令單一敵方暗系攻擊力減半 5 回合。
- 天雷聚陽鼎：5 回合提升單人光系攻擊 30%。

兩件法寶槽意味每名隊員可同時以雷公鎚與暗黑魔樽處理蚩尤主要的雷／暗壓力；實際抗性如何與角色、裝備、護罩相加或相乘，仍是 native engine 待驗證項目。法寶資料與取得交叉參考見[法寶攻略](https://annion.kingbig.idv.tw/gameraiders/?p=2622)。

### 技能、物品與護駕

### 原生護駕不提供角色抗性

**官方檔內說明，Steam HD 4.0.5，2026-09-04。** `generated/guardian-cards.csv` 的 97 張原生 `IT_12` 護駕，其召喚 `AttackEffect.iResistAttr` 都是 `0`；原生資料沒有任何一張護駕把「抗性」定義成召喚後附加給角色的效果。

這不代表所有護駕的**怪物本體**沒有屬性值：同一批 97 張卡中，86 張的戰鬥資料帶有至少一個 `Attr*` 值，82 張至少有一個負值（抗性）。那些欄位描述護駕作為戰鬥物件／敵人時的屬性，而不是角色裝備護駕後獲得的抗性。既有隔離實測亦顯示護駕欄的 `Add*` 能力值會套用，但卡片 `Attr*` 不會原生套用至角色；直接寫入玩家戰鬥副本的 `AttrPoison` 路徑另已否決，見[userdata 抗性邊界](../../runtime-api-and-data-model.md#戰鬥中的角色資料)。故目前不得把任何原生護駕列為玩家雷、暗、毒等抗性的來源。

### 五蚩尤的資源壓力（不是傷害模擬）

若不使用 MP 回復，僅以四人 Lv60 的初始 MP 計算：李靖可施放無相如來 3 次、卡瑪可施放白虎星降 4 次、賽特可施放火神降臨 2 次。把 `iAttackPoint` 只當作比較用資源點數，三者對五個目標合計為 `(3×3000 + 4×3500 + 2×2500)×5 = 140,000` 點。**2026-09-06 校正：這不是實際 HP 傷害，不能以低於150,000判定輸出不足；也尚未計入其他隊員、普攻、絕招與消耗體力的物品。**

若先以天雷聚陽鼎強化李靖，並暫按資料表的光弱 60% 與光增 30% 作**非最終傷害的代理估算**，李靖的三次行動會相當於每目標 18,720 點；加上卡瑪與賽特的原始點數，代理總量約為 188,600 點。這只是乘法假設下的資源敏感度，不證明能擊破五隻；實際傷害、增益疊加、存活與敵方行動壓力仍需量測。

## 4. 最強隊伍能打幾隻蚩尤？

目前可以作出下列分級判定；這不是未測就宣稱的勝率。

| 編制 | 判定 | 原因 |
| --- | --- | --- |
| 1 隻 | **原版可設計為可勝** | 蚩尤原本就是可選隱藏 Boss；滿等、正確抗性、光系與補給有合理戰術路線。 |
| 2 隻 | **待實測的高難模式** | HP 加倍到 60,000，敵方行動數也加倍；可用全體光／風輸出與雷暗抗，但一次 AI 連鎖足以快速破壞回復節奏。 |
| 3–4 隻 | **不宜稱為原版平衡挑戰** | 全體雷／暗技能密度與 90,000–120,000 HP 使戰鬥更取決於物品庫存、抗性疊加和 AI 隨機，而非原版成長曲線。 |
| 5 隻 | **實驗／後期賞金級** | 150,000 HP、五次敵方行動；沒有初始 MP 回復時的全體輸出資源就已經吃緊。若開放軒轅劍僮與完全成長法寶，可能存在取勝路徑，但仍不能在未做傷害實測前聲稱「公平或穩定可勝」。 |

建議自由挑戰把 1 隻當成「標準首領」、2 隻作「高難」、3–5 隻明確標為「極限／實驗」。若日後要把 5 隻做成可重複目標，應選擇下列其中一種：

1. 給它固定的特別獎勵與首次完成記錄，避免完整原版 EXP／金錢／掉落無限刷取。
2. 讓玩家選「普通挑戰」或「契約挑戰」：後者允許一次特別收妖，但沒有一般戰利品。
3. 以逐隻擊破／分階段血量取代同時五隻，保留總挑戰感但降低同回合五個全體法術的波動。

## 5. 收妖與新活物卡的設計結論

### 原版靈契門檻（官方檔內說明）

**官方檔內說明，Steam HD 4.0.5，2026-09-04。** 原版解出檔
原版 `Function_Repository.lua`（來源指紋與重建方式見[原版腳本基線](../../engine-research-workflow.md#steam-hd-405-原版腳本基線)） 的
`Function.CheckObsolt(player, target)` 會回傳靈契的機率值。`player` 是**本次施放靈契的角色**，不是隊伍平均或最高等級；`target` 使用戰鬥副本中的 `NPCData.Level`、`HP` 與 `MaxHP`。

在計算機率前，它按此順序直接回傳 `0`：目標 HP `<=0`、已死亡、已隱藏、沒有 `ItemTemp` 資料、`IT_06=true`（劇情類）、`IT_12` 不存在／為假（非活物）、或該種族沒有 `GameData.Race[Race].catch=true`。因此，血量壓低並不能繞過這些資格限制。

全部資格通過後，令 `d = 玩家等級 - 目標等級`，`h = 目前 HP / 最大 HP`，原函式的回傳值如下：

| 等級差 `d` | 血量條件 | 原函式回傳值 |
| --- | --- | ---: |
| `d >= 10` | 任意存活 HP | 100 |
| `5 <= d <= 9` | `h <= 1/3` | 100 |
| `5 <= d <= 9` | `h > 1/3` | 80 |
| `0 <= d <= 4` | `h <= 1/3` | 100 |
| `0 <= d <= 4` | `h > 1/3` | `20 + 10d`（20、30、40、50、60） |
| `-6 <= d <= -1` | `h <= 1/3` | 100 |
| `-6 <= d <= -1` | `h > 1/3` | `20 + 5d`（15、10、5、0、-5、-10） |
| `-11 <= d <= -7` | `h <= 1/4` | 100 |
| `-11 <= d <= -7` | `h > 1/4` | 0 |
| `d <= -12` | 任意 HP | 0 |

**護駕的原版AI／死亡成本，官方檔內Lua，HD4.0.5，2026-09-07。** `OnEvent_Battle.Battle_KeeperInit.main(index,itemtabIdx)`保存對應背包物件並初始化技能資料；`Battle_Dead.main`在我方data.isKeeper分支尋找同一背包物件，Stock減一後呼叫ItemClass.DelItem扣一份。這是正常事件流程的原版實作，不外推未觀察模式或中斷。`OnEvent_BattleNPCAI.main`的普通技能與特殊攻擊只有剩餘次數>0才入池；CR治療池沒有相同正值篩選、選中仍扣次數，所以不能把CR初始計數當成硬性治療次數上限。治療目標取主角HP百分比清單，不把召喚治療一律算自療或全體。實際native耗費、召喚數上限與命中仍須人工核對。

**取得鏈補充，原版資料推導＋Lua預覽mock，2026-09-07。** 不能只以直接販售／GetItem／掉落參照判定護駕或靈藥供應。以石國兩固定商店清單作種子、保留有序東西方规则、原生材料分類／等級及同級並列界線，可找到96種正常原生IT_12候選中89種的完整商店材料鏈，亦涵蓋蟠桃、仙爐灰、仙魄香、仙蓮子。用到的97個有序配方均由隔離原版`OnEvent.Obsolt.main(1,2,0)`預覽核對；僅證明該資料／預覽條件，不是89種原生交易／无限回購實測。精確種子、排除、腳本、指紋與產物見[材料鏈驗證結果](../../../../swd3-cai-demon-king-mod/GUARDIAN-SUPPLY-AND-AI.md#材料鏈驗證結果)。一次性劇情材料的多份供應只能證明指定庫存足夠；沒有可取得種子的配方環不能單獨證明可持續生產。

新增契靈明顯擴大可用戰力，屬MOD規格而非原版上限。分析工具保留分池比較快照；本次專案採用方式、牛魔王／蚩尤／撒旦／鬥戰聖佛的取捨，以及蔡魔王首勝排除規則，集中在[蔡魔王平衡目標](../../../../swd3-cai-demon-king-mod/BALANCE-TARGETS.md)，不把其數值提升成引擎規則。

點數、回復定義及持續回合均不是這次人工實測。**iAttr=10不能當成真實傷害或無視全部抗性**；封魔可否被某角色免疫、吸SP扣多少、全體是否含在場護駕，均需實際目標與資源變化。血靈還魂的 `bWideRange=true`／`bSnatchHP=true` 定義見 `GameData_AttackEffect.lua:4752–4763`；吸回總量、比例、過量／吸收／免疫後處理不能假設等於4000×4。

**治療目標排序校正。** `Function_Repository.lua:195–209` 的 `Function.CheckAllEnemyHP` 保存 `{index, currentHP, GUID, HPpercent}`，`:206` 比的是第二欄**目前HP絕對數值**；`OnEvent_BattleEnemyAI.lua:91–110` 使用第一列的第四欄百分比算治療權重，並保存第一列的index作目標。不是「先挑最低HP百分比」。例如同陣營小怪HP100/100與Boss10000/30000，前者因當前HP較少排第一；若治療次數仍為正，它的100%使本輪治療權重為0，不能假定AI必定救剩1/3血的Boss。這是Lua控制流推導，非該混隊實機結果。

治療槽剩餘次數正值時，每槽插入 `floor((100-HPP)/10)` 個選項；次數≤0時仍插入一個。選中CR時（同檔`:201–220`附近），`AI_TargetIsEnemySide=false`，AI_Target用上述同陣營目標，再讀AddHP寫RestorHP。因此**單體補血也可能支援另一隻敵人**，不能一律當自療；欄位送出不等於native已完成正確回血。

普通技能／特殊攻擊也有次數耗盡後最低權重，且普攻權重會隨AttackCount及可用技能變動；`SkillRate=7`不是7%或每7回合一次。治療槽有重複技能時，重複項各自參與抽選，不能先去重再估機率。

同版一般狀態選擇玩家目標的迴圈（`OnEvent_BattleEnemyAI.lua`，搜尋 `player.isPlayer`，約`:145–170`）只保留主角判斷，`or player.isKeeper`被註解；不能預先把高HP召喚護駕當成會替玩家吸走所有單體攻擊的坦克。瘋狂分支、全體作用範圍及其他AI腳本需另看，不外推為所有攻擊都不會碰護駕。

5個無效CR技能1來源是28撒旦、7康那里士、191樂仙女、153瓦雀、399修道院院長。這是資料引用缺口，不是本次已重現的閃退；不把空效果列當0點正常治療，也不自行修補原版資料。異常條目与蔡魔王438原本錯置的1683效果引用皆在壓力表保留缺失標記，供正式選敵／技能驗證選案。

多敵人的關鍵量測不是只算HP總量：要同時記錄一次救援窗口內的全體受傷分布、倒地數、封魔／中毒／資源吸取，以及敵方各目標的實際回復。全體攻擊不一定永遠強於單體：有全體補血且能及時使用時，集中擊倒一名支援者可能更危險；應以隊伍狀態和可用反制比較。
