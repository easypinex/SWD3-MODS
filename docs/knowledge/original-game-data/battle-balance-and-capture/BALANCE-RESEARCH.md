# 原版戰鬥資料：能力上限、敵人強度與收妖

研究日期：2026-09-03。資料版本為本工作區解出的 Steam HD 4.0.5 `script_index.ssmod`。本文件保存原版資料與其可驗證推論；它不直接修改遊戲資料或任何插件規則。文中的「自由挑戰」建議是目前已知的整合案例，不是資料本身的專屬用途。

## 結論先行

1. 四名正式隊員的原版等級上限都是 Lv60；其「只含角色成長」的滿等數值可精確重算。但這不是遊戲的絕對能力上限，因為原版有可在平時使用、增加 HP／MP／SP／力量／耐力／智慧／敏捷等上限的道具。
2. 單隻蚩尤是原版刻意設計的隱藏終局挑戰；五隻蚩尤則是 150,000 HP、每一敵方回合最多五次行動的非原版編制。依可見資料，不應把「五隻」視為與單隻相同等級的公平挑戰。
3. 蚩尤 HP≤15% **仍不能**用原版靈契收服：它同時是 `IT_06` 劇情類、不是 `IT_12` 活物卡，且 Lv80 對 Lv60 的等級差已超過原版允許值。若開放，必須做成僅限自由挑戰的契約規則，並將結果交換為新的活物卡 ID。
4. 現行自由挑戰的 193 個可戰鬥資料中，96 個已有 `IT_12` 活物卡、97 個沒有。不能假設所有可挑戰敵人都能被原版靈契；更不應直接把劇情敵人的範本改成活物卡。

### 為何這不是「絕對最強」

原版物品資料中有 `Calculation=256` 且 `UsePlace=2` 的平時能力上限道具。例如蜂王露 +10 力量、活靈芝 +100 SP、三葉雪桑果 +100 HP、七合龍爪花 +100 HP／MP／SP。它們的物品定義、價格與數值已列在 `generated/permanent-growth-items.csv`；但已解出的 Lua 未能證明商店庫存是否無限、每個存檔可取得份數，或 native engine 的最終能力硬上限。因此：

- 「只用等級成長」的滿等基準：**已可重算**。
- 「正常遊玩可取得的一次性總量」：**待補劇情／商店／掉落來源索引**。
- 「利用可重複購買／煉化後的理論絕對值」：**待驗證 native 上限與庫存**，目前不能宣稱有固定最大值。

## 2. 原版可達成的終局戰術資源

### 裝備與法寶

已解出的數值與攻略交叉一致的終局武器候選為：賽特的軒轅劍 `+590 ATK`、妮可的萬鈞神弩 `+200 ATK`、卡瑪的四極皇霸刀 `+215 ATK`、李靖的憾天神槍 `+248 ATK`。每項的角色限制、加成與特殊能力都在 `generated/equipment-and-artifacts.csv`。

對蚩尤的防禦核心不是單純堆 DEF，而是雷電與暗系防護：

- 雷公鎚：法寶修練後「抵抗敵方雷電系法術 80%」。
- 暗黑魔樽：法寶修練後「抵抗敵方暗系法術 80%」。
- 金鐘罩秘笈：護罩指令消耗 SP；攻略資料記錄修練後為 DEF +70%、最長 6 回合。
- 三教霞光鏡：可令單一敵方暗系攻擊力減半 5 回合。
- 天雷聚陽鼎：5 回合提升單人光系攻擊 30%。

兩件法寶槽意味每名隊員可同時以雷公鎚與暗黑魔樽處理蚩尤主要的雷／暗壓力；實際抗性如何與角色、裝備、護罩相加或相乘，仍是 native engine 待驗證項目。法寶資料與取得交叉參考見[法寶攻略](https://annion.kingbig.idv.tw/gameraiders/?p=2622)。

### 技能、物品與護駕

### 原生護駕不提供角色抗性

**官方檔內說明，Steam HD 4.0.5，2026-09-04。** `generated/guardian-cards.csv` 的 97 張原生 `IT_12` 護駕，其召喚 `AttackEffect.iResistAttr` 都是 `0`；原生資料沒有任何一張護駕把「抗性」定義成召喚後附加給角色的效果。

這不代表所有護駕的**怪物本體**沒有屬性值：同一批 97 張卡中，86 張的戰鬥資料帶有至少一個 `Attr*` 值，82 張至少有一個負值（抗性）。那些欄位描述護駕作為戰鬥物件／敵人時的屬性，而不是角色裝備護駕後獲得的抗性。既有隔離實測亦顯示護駕欄的 `Add*` 能力值會套用，但卡片 `Attr*` 不會原生套用至角色；直接寫入玩家戰鬥副本的 `AttrPoison` 路徑另已否決，見[userdata 抗性邊界](../../runtime-api-and-data-model.md#戰鬥中的角色資料)。故目前不得把任何原生護駕列為玩家雷、暗、毒等抗性的來源。

可見資料中，五蚩尤最有意義的輸出與維持資源如下。

| 資源 | 原始點數／效果 | 消耗 | 對五蚩尤的意義 |
| --- | ---: | ---: | --- |
| 李靖：無相如來 | 光、全體、3,000 | 300 MP | 蚩尤 `AttrLight=6`，資料表標記為懼怕光 60%；是唯一直接對全隊蚩尤利用弱點的高點數法術。 |
| 卡瑪：白虎星降 | 風、全體、3,500 | 320 MP | 單輪全體原始點數最高；蚩尤沒有風抗性資料。 |
| 賽特：火神降臨 | 火、全體、2,500 | 250 MP | 有效的次級全體輸出。 |
| 軒轅劍僮（蚩尤戰後） | 光、單體、8,000 | 600 SP | 蚩尤掉落後的極高單體光系點數；用於第一次蚩尤前屬於循環依賴，不能當作初戰前提。 |
| 仙蓮子 | 全體 HP／MP／SP 100% 並解除瀕死 | 消耗品 | 長戰維持的最強明確補給；是否能大量購入需按存檔實測。 |

資料表的「所有戰鬥可用物」已包含補血、補 MP／SP、復活、解異常、增益／減益、法寶和護駕，不只列上述策略：見 `generated/battle-usable-items.csv` 與 `generated/guardian-cards.csv`。已知戰術道具的取得地與持續回合可由[道具攻略](https://annion.kingbig.idv.tw/gameraiders/?p=2616)交叉參考；原始數值仍以本工作區 CSV 為準。

### 五蚩尤的資源壓力（不是傷害模擬）

若不使用 MP 回復，僅以四人 Lv60 的初始 MP 計算：李靖可施放無相如來 3 次、卡瑪可施放白虎星降 4 次、賽特可施放火神降臨 2 次。把 `iAttackPoint` 只當作比較用資源點數，三者對五個目標合計為 `(3×3000 + 4×3500 + 2×2500)×5 = 140,000` 點；這甚至低於五隻蚩尤 150,000 HP 的總和，還未計算抗性或防禦。

若先以天雷聚陽鼎強化李靖，並暫按資料表的光弱 60% 與光增 30% 作**非最終傷害的代理估算**，李靖的三次行動會相當於每目標 18,720 點；加上卡瑪與賽特的原始點數，代理總量約為 188,600 點。這說明五隻並非邏輯上完全不能擊破，但它需要長戰補 MP／SP、讓全員存活、成功維持增益，且仍受 native 傷害公式與敵方回合壓力支配。

## 4. 最強隊伍能打幾隻蚩尤？

目前可以作出下列分級判定；這不是未測就宣稱的勝率。

| 編制 | 判定 | 原因 |
| --- | --- | --- |
| 1 隻 | **原版可設計為可勝** | 蚩尤原本就是可選隱藏 Boss；滿等、正確抗性、光系與補給有合理戰術路線。 |
| 2 隻 | **待實測的高難模式** | HP 加倍到 60,000，敵方行動數也加倍；可用全體光／風輸出與雷暗抗，但一次 AI 連鎖足以快速破壞回復節奏。 |
| 3–4 隻 | **不宜稱為原版平衡挑戰** | 全體雷／暗技能密度與 90,000–120,000 HP 使戰鬥更取決於物品庫存、抗性疊加和 AI 隨機，而非原版成長曲線。 |
| 5 隻 | **實驗／後期賞金級** | 150,000 HP、五次敵方行動；沒有初始 MP 回復時的全體輸出資源就已經吃緊。若開放軒轅劍僮與完全成長法寶，可能存在取勝路徑，但仍不能在未做傷害實測前聲稱「公平或穩定可勝」。 |

建議自由挑戰把 1 隻當成「標準首領」、2 隻作「高難」、3–5 隻明確標為「極限／實驗」。若日後要把 5 隻做成可重複目標，應選擇下列其中一種：

1. 給它固定的特別獎勵與首次完成記錄，避免完整原版 EXP／金錢／掉落無限刷取。
2. 讓玩家選「普通挑戰」或「契約挑戰」：後者允許一次特別收妖，但沒有一般戰利品。
3. 以逐隻擊破／分階段血量取代同時五隻，保留總挑戰感但降低同回合五個全體法術的波動。

## 5. 收妖與新活物卡的設計結論

### 原版靈契門檻（官方檔內說明）

**官方檔內說明，Steam HD 4.0.5，2026-09-04。** 原版解出檔
原版 `Function_Repository.lua`（來源指紋與重建方式見[原版腳本基線](../../engine-research-workflow.md#steam-hd-405-原版腳本基線)） 的
`Function.CheckObsolt(player, target)` 會回傳靈契的機率值。`player` 是**本次施放靈契的角色**，不是隊伍平均或最高等級；`target` 使用戰鬥副本中的 `NPCData.Level`、`HP` 與 `MaxHP`。

在計算機率前，它按此順序直接回傳 `0`：目標 HP `<=0`、已死亡、已隱藏、沒有 `ItemTemp` 資料、`IT_06=true`（劇情類）、`IT_12` 不存在／為假（非活物）、或該種族沒有 `GameData.Race[Race].catch=true`。因此，血量壓低並不能繞過這些資格限制。

全部資格通過後，令 `d = 玩家等級 - 目標等級`，`h = 目前 HP / 最大 HP`，原函式的回傳值如下：

| 等級差 `d` | 血量條件 | 原函式回傳值 |
| --- | --- | ---: |
| `d >= 10` | 任意存活 HP | 100 |
| `5 <= d <= 9` | `h <= 1/3` | 100 |
| `5 <= d <= 9` | `h > 1/3` | 80 |
| `0 <= d <= 4` | `h <= 1/3` | 100 |
| `0 <= d <= 4` | `h > 1/3` | `20 + 10d`（20、30、40、50、60） |
| `-6 <= d <= -1` | `h <= 1/3` | 100 |
| `-6 <= d <= -1` | `h > 1/3` | `20 + 5d`（15、10、5、0、-5、-10） |
| `-11 <= d <= -7` | `h <= 1/4` | 100 |
| `-11 <= d <= -7` | `h > 1/4` | 0 |
| `d <= -12` | 任意 HP | 0 |

門檻使用 `<= MaxHP / 3` 或 `<= MaxHP / 4` 的精確比較；例如最大 HP 100 時，1/3 門檻是目前 HP `<=33`。特別要注意，原 Lua 在目標高 5 或 6 級、且 HP 高於 1/3 時會分別回傳 `-5`、`-10`，**沒有自行夾到 0**。

原生手動 action 6 與 Lua `CheckObsolt` 的關係、wrapper 的否決證據見[原生靈契](../../native-capture-and-eligibility.md#公開-lua-能力與不可採用的推論)。下表是原版資料層初篩，不是實機捕捉率；native 亂數端點尚未獨立驗證。

| 審計結果 | 數量 |
| --- | ---: |
| 可挑戰戰鬥資料 | 193 |
| 已有活物卡 (`IT_12`) | 96 |
| 沒有現有活物卡 | 97 |
| 在 Lv60 前提下通過資料層靈契初篩 | 82 |
| 被 `IT_06` 劇情類阻擋 | 51 |
| 被非 `IT_12` 阻擋 | 46 |
| 有 `IT_12` 但種族沒有 `catch=true` | 14 |

上述原因採原版檢查順序，不能把各欄相加作為互斥總數。
