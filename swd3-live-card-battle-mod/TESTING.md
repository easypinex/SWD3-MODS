## 實機驗收

本版的輸入安全性由 `ESC.Menu` 原生選單保證，已不使用 `DrawMenuAfter` 覆蓋面板，也不使用 `H/I/J/K/L` 等替代按鍵。`ESC.Menu` 的列文字會傷害 UTF-8 尾端；`nativeMenu` 統一在每一列加入四個不可見 ASCII 空白作為緩衝，已實機確認可保留正確中文。詳見 [原生選單研究證據](../research/active/swd3-native-menu-probe/ENGINE-UI-RESEARCH.md)。

1. 開啟物品欄，記住目前反白項目與分類，按 `F9`；標題應為「挑戰模式」。
2. **先驗文字，不要進入功能測試。** 標題不得為 `0`；主選單中文、`[]`、`/` 與計數不得出現方框、亂碼、缺字或額外附加值。再進入一個實際怪物清單，確認 `StringDB` 的怪物中文名稱正常。這同時驗證每列的 UTF-8 空白緩衝；此項失敗即停止，不測戰鬥。
3. 主選單用方向鍵、確認鍵與滑鼠列選取；確認原生物品欄不會同時切換分類、反白或使用物品。
4. 在每個子選單確認首列、末列都是「返回上層」；任選其一或點選選單空白處，都應安全返回上一層。主選單選「返回物品欄」後回到物品欄。`Esc` 已實測無反應且不會進入 MOD 事件記錄，不能列為驗收方式。
5. 確認回到物品欄時反白、分類、使用中狀態回到初始值，但背包物品數量完全不變。這是已接受的引擎限制。
6. 從「我的活物」選同一張兩次，再從「神魔異事錄 → 種族」選三張未持有的活物；確認「已選隊伍」為 5 張，且可逐張移除／清空。
7. 含大量活物或種族的清單可用上一頁／下一頁，每頁最多 7 筆資料；含首尾返回與翻頁列時，選單仍應保持易讀且所有列可點選。
8. 在神魔異事錄中確認撒旦賽特（`ItemTemp[75]`、`Race=23`）可列出並可選；它不是持有活物，所以選取與戰後都不得產生 `Stock`。
9. 在「難度調整」逐一確認生命、攻擊傷害、防禦、速度與技能傷害皆預設 `1.0x`，可在 `0.5x`～`2.0x` 間每次調整 `0.1x`，並會在上、下限停止。選單必須顯示五項係數的算術平均；平均低於 `1.0x` 時顯示「本次無獎勵」，達到或超過 `1.0x` 時提示消失。特別驗證生命 `0.9x`、攻擊傷害 `1.1x`、其餘 `1.0x` 的平均為 `1.0x`，仍保留獎勵。
10. 選好至少三張隊伍並調整一項難度後，關閉選單、重新按 F9、完成一場挑戰後再按 F9；隊伍數量與五項難度都必須保留。完整重啟遊戲後，則必須回到空隊伍與全數 `1.0x`；這是避免過期背包槽位跨讀檔誤用的安全設計。
11. 開啟 SS2DConsole 後進戰。每場應先出現一行 `challenge difficulty:`，列出五項係數、平均與 `rewards=normal/disabled`；每隻敵人再出現一行 `difficulty applied:`，列出 `before`／`after` 的 HP、MaxHP、ATK、DEF、SPD、WIS。先以這些實際 runtime 值確認係數已寫入，再比較戰鬥畫面與傷害。
12. 以單張、三張、五張與同卡重複五張各開始一次；敵方數量、ID、位置與選取順序正確。對可清楚觀察的敵人，分別驗證生命、攻擊、防禦、速度的 `0.5x`、`1.0x`、`2.0x` 效果；技能傷害係數目前以敵方 `WIS` 實作，需以同一敵人的可重複技能比較確認實際傷害變化與預期一致。
13. 對持有活物開戰：`Count`／`Count_New` 不減，只有 `Stock` 暫時增加；對圖鑑／首領活物開戰：不應新增任何 `Stock`。
14. 難度平均 `>=1.0x` 時，驗證勝利的原版經驗、金錢與一般掉落照常結算。難度平均 `<1.0x` 時，驗證經驗、金錢、法寶經驗、絕招經驗與一般掉落皆為零；勝敗、逃跑、切圖、讀檔與開戰失敗後，敵人的原始 `GainEXP`、`GainGold`、一般掉落與持有卡 `Stock` 都必須恢復。自由挑戰戰敗時應顯示戰鬥中止並回到遊戲，**不得**進入 Game Over／主選單。
    - 特別驗收：以挑戰戰敗進入 Game Over、返回標題並讀檔後，開啟物品欄按 `F9` 必須能再次開啟選單；Console 不得出現 `selector is already running`。
15. 對持有與虛擬挑戰敵人分別測試收妖／靈契；若未啟用全魔物靈契，引擎新增同 ID 活物後背包淨數量不得增加。若全魔物靈契已武裝且目標在其卡庫，Console 必須顯示 `delegated captured challenge card` 與該 MOD 的 `capture exchange confirmed`，最後得到映射靜態卡、沒有來源物殘留。
16. 同時啟用既有 F8 熟練度 MOD 與煉化診斷 MOD，並以兩種載入順序重做第 12～14 項。

- **已通過自動 mock 與封裝反解，2026-09-06，v0.5。** 同時提供全魔物靈契 runtime 時，挑戰戰的原生收服成功會記錄 `delegated captured challenge card`，自由挑戰不會排程移除來源物；卡庫 MOD 因而可在戰後完成自己的靜態卡交換。未提供該 runtime 時，既有的防複製清理規則維持不變。成品為 `16,312` bytes，SHA-256 `CFA4F2701BA7078E5711369C4AB7CB722C4FCCDF36D821D5FD4D7C2A446B80A9`。
- **已通過，2026-09-04，v0.4 候選版。** 自由挑戰的九天玄女（ID `149`）在生命係數 `0.5x`、其餘係數 `1.0x` 時，Console 顯示 HP／MaxHP 從 `2200/2200` 變為 `1100/1100`；證實本場敵方副本的生命倍率實際生效，且未改寫原始敵人範本。
- **待驗收後才可發布。** 攻擊、防禦、速度與智慧（技能傷害）係數的實際戰鬥效果，以及平均低於 `1.0x` 時所有獎勵與一般掉落都為零，仍須依第 12、14 項完成實機驗收。

## 已知引擎限制與安全行為

- **2026-09-06 使用者回報／待驗證：**蔡魔王可顯示資訊，但開始挑戰後崩潰。原版資料核對發現 `ACT=438` 未在動畫表宣告、特殊攻擊 `1683` 無對應攻擊效果；尚未取得配對 Console／dump 或完成修復。此角色及繼承資料的契靈卡 `10096` 不得視為已通過戰鬥驗收。證據、修正方案與驗證順序見[蔡魔王評估](BALANCE-AND-SAFETY-AUDIT.md#蔡魔王開戰崩潰評估2026-09-06)。

- 公開 `OnEvent.InputClick` 回傳 `true` 不能攔截物品欄輸入；舊版左側自繪面板與背景圖方案已停用。
- `ESC.Menu` 必須在 `GameFunc.RunScene` 場景 coroutine 內呼叫；它接管方向鍵、確認與滑鼠列選取。點選空白處會回傳 `0`；`Esc` 已實測無反應且 Lua 事件不會收到它。正式流程只將已確認的 `0` 視為返回，且不要再從 Lua 呼叫 `DLGClose`。
- `ESC.StartBattle` 可能直接中斷原生選單 coroutine；MOD 在**呼叫它之前**立即清除 `selectorRunning` 與選單資料，不能依賴戰後、換圖或讀檔才清理。`Battle_RestoreItem`／`MapLoading` 仍負責釋放預留；物品欄繪製時的遺留偵測只作防呆。
- 自由挑戰進入戰鬥時只對 `MOD_CARD_CHALLENGE` 呼叫原版腳本已使用的 `BSC.NoOVER()`；最後一名我方倒下時呼叫 `BSC.BattleBreak()` 中止本次挑戰。此路徑不套用到任何原版戰場；需完成實機敗北驗收後才可視為已證實。
- 原生選單返回物品欄後不會保存反白、分類或使用暫態狀態；本 MOD 不嘗試寫入未公開的引擎狀態。
- 遇到 `ESC.Menu`／`RunScene` 呼叫失敗時，流程會記錄 Console 並安全返回，不建立戰鬥或預留。

4. 只在上述實機驗收完成後才發布或上傳工作坊。
