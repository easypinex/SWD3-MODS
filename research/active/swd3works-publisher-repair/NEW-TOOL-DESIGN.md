# SWD3 MOD Studio：全新發佈與維護工具提案

2026-09-06。名稱 **SWD3 MOD Studio**；已完成 [發佈與維護桌面版 0.3.0](DESKTOP.md)，經真實 Steam 私人作品新建、更新與下載驗證。以下仍是完整產品路線圖，包含尚未實作的封裝編輯器、安裝管理及遊戲／DLC 管理。0.3.0 採本機 WPF Framework 4.8 與原子 JSON 保存；下方 .NET 10／SQLite 為後續提案，非目前相依。原工具錯誤證據見[研究 README](README.md#f1成功後空值例外與追蹤紀錄遺失)。

## 產品與完整替代的定義

獨立 Windows 桌面程式，整合 MOD 專案、封裝、Steam 發佈、既有作品維護與本機安裝管理。日常工作不需要 `SWD3Works.exe`；新 UI、流程及資料層使用自有來源實作，不改名覆蓋或借用原工具的視窗／內部物件。

**1.0 完成所有 MOD 製作、發佈與管理工作；2.0 補齊原啟動器的遊戲／1999 DLC 附屬功能，才可宣稱整支 SWD3Works 的功能替代。** 第一版只做上傳按鈕不足以稱為完整替代。

仍可呼叫正版遊戲隨附的 `SS2Dtool.exe` 封裝／解包及 `SS2DConsole.exe` 診斷。這些與 SWD3Works 是不同工具；連它們也完全重寫需另行研究封包與 Console 協定，不列為本方案必要前置。

## 五個主要畫面

| 工作區 | 核心功能 |
| --- | --- |
| 我的作品 | 從 Steam 查自己的已發佈作品；顯示 ID、可見度、更新時間、本機綁定；搜尋、重新整理、URL／ID 匯入、私人及未訂閱作品 |
| 本機專案 | 選取現有 MOD 專案或 `.ssmod`；綁定原 Workshop ID；維護多語言標題／說明、預覽、版本與更新說明；來源搬家後重新指定位置 |
| 發佈與版本 | 封裝驗證、預覽變更、上傳進度、更新原作品；保存每版內容快照、雜湊與提交結果 |
| 已安裝 MOD | 區分本機／Steam 訂閱來源；安裝、啟停、排序、下載狀態、版本／來源衝突、設定備份與還原 |
| 工具與診斷 | 封裝／解包、Console、遊戲啟動、待確認操作、錯誤紀錄及診斷匯出；完整替代階段補附屬設定 |

預設繁體中文。一般畫面顯示「已上傳」「已保存」「結果待確認」「需要重新指定內容目錄」等狀態；API 名稱及堆疊放進診斷頁。

### 找回目前失聯的作品

識別登入 Steam 帳號 → 列出作者作品 → 選作品 → 綁定本機成品／專案 → 核對遠端文案及可見度 → 發佈更新。

不要求舊 `.mod` 紀錄，也不要求訂閱自己的作品。更新保留 Workshop ID，不因工具遷移重建工作坊頁面。帳號權限、私人項目可見性及 AppID 篩選仍須原型實測。

作者清單用 `CreateQueryUserUGCRequest` 的 Published 分類並遍歷所有頁，與訂閱列表分開。Valve 定義的 Published 和 Subscribed 是不同列表。[Valve ISteamUGC](https://partner.steamgames.com/doc/api/isteamugc#EUserUGCList)

### 新建與更新

- 新建先保存草稿，預檢內容；取得遠端 ID 後立即落盤，再提交完整文字、內容及預覽，預設私人。
- 更新明確顯示原 ID、遠端／本機差異，只提交本次選定欄位。文字／可見度更新不強制重新上傳整包，空白草稿不自動清除其他語言。
- 保存的上一版快照可作為一筆新的更新重新提交；這不是 Steam 任意歷史版本回滾功能。快照不存在就不能宣稱能還原。
- 上傳中仍可瀏覽其他頁；同一作品序列提交。工作者失效不應使主視窗卡死，成功提示不阻塞 Steam 回呼。

## 技術方案與可行性門檻

**專案決策：** Windows、C#／WPF、.NET 10 LTS，採 UI、操作協調層、Steam 工作者程序、封裝 adapter、本機資料層。Microsoft 現行支援表列 .NET 10 為 LTS，支援至 2028 年 11 月。[Microsoft 支援政策](https://dotnet.microsoft.com/en-us/platform/support/policy)

目前只盤點到本機 .NET SDK 8.0.204；實作需準備鎖定版本的 .NET 10 SDK。UI 優先 Windows x64，Steam 工作者架構依實際 DLL 匹配決定。

```text
WPF 主視窗 ↔ 操作協調層 ↔ 本機資料庫／版本快照／日誌
                  ├─ Steam 工作者 ↔ 相容的 Steam API
                  └─ 封裝工作者 ↔ SS2Dtool／反解驗證
```

Steam 工作者集中執行 Init、query、create、update、callbacks 與 shutdown，單執行緒 pump 有重入防護。主視窗以本機 IPC 非同步收發帶操作 ID 的請求／結果；工作者斷線可重新啟動，但不自動重送有遠端副作用的請求。

**先驗證 Steam，再投入完整介面：**

1. 識別正版安裝、AppID `1638230`、Steam 依賴與版本 hash，使用成套相容的包裝器／原生 DLL；不把最新 wrapper 直接配舊 DLL。[Steamworks.NET 的版本匹配提醒](https://steamworks.github.io/steammanager/)
2. 在獨立工具目錄成功初始化，核對實際 AppID／登入帳號，查作者作品、分頁及指定 ID。設定 AppID 不等於取得發佈權限。
3. 驗證原包裝器與新 runtime／架構相容性；若不相容，Steam 工作者可單獨採 .NET Framework 4.8，UI 仍用 .NET 10。成套新版 SDK 另驗證後才升級。
4. 對指定私人測試項目完成新建、同 ID 更新、重啟找回及遠端內容校對。Init 成功或拿到 handle 不算通過。

若 Steam 初始化／權限條件阻擋，先定位並調整部署，不能承諾「改 AppID 即可」。可先提供本機功能，但此時不稱為發佈替代完成。

## 保存與中斷恢復

遠端作品以 `(AppID, SteamID, WorkshopID)` 識別，本機專案用獨立 project ID；同作品一次只允許一筆寫入操作。Steam／Workshop ID 用十進位字串保存與匯出。

- **SQLite：** 固定每使用者可寫目錄，保存作品快取、綁定、草稿、操作與子請求、遠端結果；交易、schema migration、備份。這是新工具資料權威，與原工具修補備案的 JSON 策略分開。
- **可攜 JSON：** 專案設定與綁定匯出／搬機；不保存 Steam 密碼或 token，匯入後重新核對帳號與所有權。
- **內容快照：** 發佈前複製驗證通過的 `.ssmod`，用 SHA-256 定址，保存預覽／文案；上傳固定快照，途中編輯來源不影響本次提交。
- **舊 `.mod`：** 只讀匯入並保留備份；遠端 ID 重新核對，本機內容／預覽失效可重新綁定。工作坊不能恢復原始碼或作者原本的磁碟路徑。

```text
草稿 → 預檢 → 建立遠端 ID（僅首次）→ ID 已保存
     → 提交中 → 遠端已確認 → 本機結果已保存 → 完成
                ↘ 失敗／部分完成／需接受協議／結果待確認
```

收到 ID 先保存再准許後續 submit；遠端成功先保存結果再通知 UI。本機保存失敗仍提供 ID 及恢復匯出，解鎖介面並明確區分「已上傳」與「紀錄未保存」。

**仍存在遠端成功、程序未及收到或保存結果即中斷的空窗。** Steam 呼叫不是本機資料庫交易，不假設有通用 idempotency key。重啟先查遠端並核對未完成操作；無法唯一配對則標示待核對，禁止自動重複 CreateItem。停止等待不表示 Steam 上傳取消成功。

離線、部分分頁失敗或私人作品暫不可見時保留綁定。其他工具修改遠端後顯示差異，由本次選定欄位決定提交，不整批覆寫陳舊快取。多語言按作品序列提交，每個 submit 有獨立狀態；重複／遲到 callback 冪等處理。

## 封裝與安裝管理

封裝依[工具語法](../../../docs/knowledge/tools-and-commands.md)與[反向驗證](../../../docs/knowledge/packaging-and-installation.md)：空的隔離建置目錄、正確 ext basename、等待完成、確認產物、反解比對，只上傳指定成品。退出碼不能單獨代表成功。

安裝管理分開讀 `Mods/modlist.txt`、`SteamMods.txt` 與 Steam 訂閱狀態；[現有 loader 證據](../../../docs/knowledge/packaging-and-installation.md#steam-hd-405-mod-loader-與-native-module-載入的界線)提供基線。實作前再確認排序、同名優先權與未知行保留，未驗證者不猜測。

啟停／排序／更新前備份，寫入前比較讀取時 hash；其他工具或遊戲已修改清單時重新整理合併，不覆蓋新內容。本機安裝只寫 MOD／清單位置，工作坊下載由 Steam 更新。執行中的遊戲標示「重啟後生效」；替換被使用檔案須協調關閉重啟。還原僅使用本工具備份，不刪除整個遊戲資料夾。
