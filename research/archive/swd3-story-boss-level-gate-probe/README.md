# 劇情首領靈契等級門檻探針

> 歷史實驗：本頁保存所列版本的操作與證據。是否重用、知識去向及未解問題，先查[研究清冊](../../README.md)；通用能力依[知識庫](../../../docs/knowledge/README.md)，不因歸檔或 mock 通過擴張為正式支援。

本探針驗證一條隔離的首領完整路徑：原版劇情首領蚩尤（ID `46`、原始 Lv80）在**建立戰鬥前**暫時符合靈契資格、把判定等級設為 Lv1後，能否由原生靈契收服並安全交換成靜態卡 ID `10017`。

它不改一般遭遇、不建立新卡，也不寫入存檔。為了讓玩家取得一次靈契操作機會，它在這場測試戰暫設蚩尤的 ATK／SPD 為 0、技能表為空；這些生存欄位與資格、等級都會在戰後逐欄還原，絕不是正式首領平衡。它依賴已啟用的「全魔物靜態卡庫」與其基線安全交換 helper。

## 操作

1. 使用可丟棄存檔，啟用靜態卡庫與本探針；停用一般遭遇資格 bridge。
2. 在安全地圖按 **F6**。Console 應記錄原始 Lv80、暫時 Lv1，以及 `IT_12=true`、`IT_06=nil`、`Race.catch=true`。
3. 戰鬥開始後，確認 `Battle_EnemyInit observed: NPCData.Level=1`；蚩尤的測試攻擊／速度／技能已暫時壓低。
4. 使用靈契收服蚩尤，勿普通擊殺。Console 必須出現 `native Battle_Dead(mode=2)`、`capture exchange confirmed: source=46, card=10017`。
5. 在物品欄反白 ID `10017` 一次，確認安全後直接結束遊戲；**絕不存檔**。
6. Console 必須顯示 `probe restored (Battle_RestoreItem): ItemTemp[46].Level=80`。

## 判讀

| 結果 | 結論 |
| --- | --- |
| 首領卡交換與反白正常 | 已驗證此一首領的完整隔離路徑；保存、停用、其他首領與正式平衡仍待獨立驗收。 |
| `capture exchange unresolved` | 停止並不保存；回報完整 Console。 |
| 離場後 Lv80 未還原 | 立刻關閉遊戲、不保存；此探針不得繼續使用。 |

**已實測完整隔離路徑，Steam HD 4.0.5，2026-09-03。** 蚩尤原始 Lv80，在進戰前暫設為 Lv1 且啟用暫時生存欄位後，`Battle_EnemyInit` 確認 `NPCData.Level=1`；原生靈契收服後先新增來源 ID `46` 與原生掉落 ID `994`，探針依開戰前基線移除新增的 ID `46`、加入靜態卡 ID `10017`。使用者已確認 `10017` 可在物品欄正常反白；戰後來源等級已還原 Lv80，未保存。此結論僅涵蓋蚩尤的隔離測試，不把 Lv1／ATK 0／SPD 0／空技能表當正式首領平衡，也不代表其他首領、存檔或停用已驗收。
