# 高等首領靈契門檻探針

> 歷史實驗：本頁保存所列版本的操作與證據。是否重用、知識去向及未解問題，先查[研究清冊](../../README.md)；通用能力依[知識庫](../../../docs/knowledge/README.md)，不因歸檔或 mock 通過擴張為正式支援。

這個隔離探針驗證：對第二個高等、非蚩尤的首領牛魔王（原版 ID `59`、Lv80），在建立戰鬥前暫設收妖資格與 `Level=1`，能否讓原生「靈契」選取目標並在成功後安全交換為靜態卡 `10024`；它不驗證正式首領平衡。

## 安全範圍

- 僅在按 F7 建立的 `HLCGP_BULL_DEMON_LEVEL` 戰場作用。
- 只暫改 `IT_12`、`IT_06`、`Race.catch` 和 `Level`，並逐欄快照還原。
- 不改 HP、ATK、DEF、SPD、技能、掉落、背包或存檔。
- 原生收服時，探針只在確認來源 ID `59` 的背包數高於開戰基線後，移除該一張並加入靜態卡 `10024`。
- 本輪可先只確認靈契選取後取消／逃跑；若要收服，使用可丟棄存檔，勿普通擊殺或保存。F5 只保留給 v0.1 已收服卻未交換的來源 ID `59` 修復。

## 操作

1. 啟用本探針與「全魔物靜態收妖卡庫」，停用一般資格及蚩尤首領探針。
2. 在安全地圖按 F7。Console 應顯示 `bridge applied before battle`，且 HP、ATK、DEF、SPD 為原始資料。
3. 確認 `Battle_EnemyInit observed: NPCData.Level=1`。
4. 對牛魔王使用靈契，確認目標沒有紅色 X；可取消／逃跑，或以獨立存檔完成一次收服。
5. 若完成收服，Console 必須顯示 `capture exchange confirmed: source=59, card=10024`；再確認 `probe restored (Battle_RestoreItem)` 且來源回到 `Level=80`。

若已在 v0.1 收服牛魔王：先正常離場、不要反白來源 ID `59`，完整重啟 v0.2 後在安全地圖按 F5 一次；Console 出現 `F5 recovery confirmed` 即表示它已換成 `10024`。此動作只應在確認該一張 `59` 是本探針剛收服的來源物時使用。

## 判讀

| 結果 | 結論 |
| --- | --- |
| 可選取且戰後 Level 還原 | 支持以相同的戰前等級 bridge 處理第二種高等首領；仍不等同全目錄已驗收。 |
| 仍顯示紅色 X | 停止，不將蚩尤作法推廣。 |
| 沒有還原訊息 | 立刻結束遊戲且不保存。 |

## 已實測結果

**已實測，Steam HD 4.0.5，2026-09-03。** 牛魔王可被原生靈契收服。Console 依序記錄 `Battle_Dead(mode=2)`、原生 `additem 59`、基線保護的 `delitem 59`、`additem 10024`、`capture exchange confirmed`，最後來源資料還原為 Lv80、ATK 800、HP 30,000。使用者確認靜態卡 `10024` 正常。這支持同一收妖等級 bridge 在兩個不同 Lv80 首領（蚩尤 `46`、牛魔王 `59`）均可運作；尚不等同所有首領與全部一般遭遇已完成正式整合。
