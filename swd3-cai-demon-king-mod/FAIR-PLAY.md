# v1.0 公平比試規格與偵測界線

2026-09-08，專案決策。使用者希望阻擋鎖血、鎖靈力、秒殺、誇張角色數值及戰中無限道具，並由蔡魔王說對應台詞。現版只對有可觀察證據的違規中止比試；不能把「未觀察到違規」等同沒有修改器。所有檢查只針對Insert獨立戰場，不掃描電腦程序、不讀取其他程式記憶體、不封鎖帳號或破壞存檔。

## 主角入場上限

| 欄位 | 上限（含） |
| --- | ---: |
| 等級 | 99 |
| 最大生命 | 30000 |
| 最大靈力／最大體力 | 各10000 |
| 攻擊／防禦 | 各5000 |
| 智慧 | 3000 |
| 速度 | 500 |

這些是本場自訂的寬鬆參賽規格，**不是從原版推導的合法最大值或修改器判定線**。正常長期使用成長道具也可能超過，因此超規格台詞不指控作弊。原版八種裝備護駕、法寶、熟練倍率與煉化MOD本身均不列黑名單。可從Insert資訊列查看規格；角色當前HP／MP／SP很高不等同超標，判定使用最大值與入場能力。

只檢查主角的已暴露數字欄位，缺欄位不當作作弊；召喚護駕不受此上限限制，包括HP99999的真契靈。暫時戰鬥加成不重套入場能力上限，避免把真夢娃娃的防禦增幅視為改值。上述門檻仍須在本版正常四人配裝實戰確認沒有意外拒絕。

## 已實作的可觀察檢查

| 條件 | 判定及對應台詞 |
| --- | --- |
| 主角入場數值超規格 | `stats`：「本事我看見了。不過這場比試有約定的界線，超過了，就得另當別論。」 |
| 本場背包出現未經已記錄物品函式的數量增減／整個背包表遭替換 | `items`：「數目對不上，我就不能當作沒看見。既然是我邀你們來，規矩也得由我守好。」 |
| 扣物函式回報成功且扣前數量足夠，但實際沒有扣足 | 同`items`；能涵蓋經此函式且返回後仍凍結數量的情形 |
| 本MOD專用資料不再符合既有就緒檢查 | `rules`：「這場的規矩出了岔子。先停下來，讓我把問題弄清楚，再談輸贏。」 |
| 主角資源出現NaN／無限值等非有限數字 | `values`：「這數目有些蹊蹺。小地方也不能將就，得查明白。」 |

以上均接「這場不計勝負，也不發獎。事情妥當了，隨時再來。」再正常中止；不判勝利、不發真契靈。全滅與勝利對話前都重查，勝利台詞中發現異常也撤銷本次領獎。比試無效的告知不算一般主線六句預算。

消耗帳只返還確實扣除的物品；沒有扣除就不創造退款。正常正向物品函式新增、Stock預留及已声明排除的交易不視為異常。還原角色資源及消耗份額沿既有流程；如外部工具連SaveData／背包容器身分都替換，會丟棄舊引用，不將舊帳硬寫入新容器，也不嘗試回滾修改器造成的整份資料變更。

## 明確沒有保證的項目

- **鎖血／鎖靈力：未可靠實作。** 生命或靈力長時間不變，可能來自減傷、回復、免消耗或沒有相應支出，不能僅憑採樣下結論。
- **改寫實際傷害的秒殺：未可靠實作。** 不以战鬥時間、選招次數、敵人突然死亡或兩次HP差額判作弊；合法快速擊殺仍能正常結算。
- **單下9000以上：未採用。** 原版存在9999效果點數的資料，不等同實傷，但目前也無可重現證據證明正常玩家傷害一定低於9000。兩次採樣可能包含多段、多人的傷害，不能充當單次命中。
- **所有無限道具工具：沒有全覆蓋。** 能跳過已包裝函式、在檢查間隙復原、同步修改對帳資料，或以正常新增函式補物的工具仍可能繞過。
- 不聲稱可以阻止會修改本MOD本身或引擎流程的工具；不把其他相容性錯誤直接認定為使用修改器。

通用事件界線由[戰鬥時序](../docs/knowledge/battle-events-and-timing.md#對-mod-設計的直接規則)維護。此文件只記錄本專案決策；原版ItemsClass扣除與序列化行為已有知識正文，沒有新的跨MOD引擎結論需要提升。

## 驗證

`tests/fair_play.lua`以原版ItemsClass驗證真扣除、正常新增、Stock、0扣除、成功但凍結、直接加物、排除交易、同一份數不重複返還，以及他場隔離。`tests/validation.lua`以真Lua coroutine驗證比試無效台詞先於離場、禁止領獎及角色原值還原；並確認正常快速擊殺不被當作秒殺工具。均屬mock，人工案例見[驗收](TESTING.md#v10-正式版候選)。
