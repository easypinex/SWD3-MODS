# 蔡魔王：獨立 MOD 可行性與內容規格

狀態：**評估草案，2026-09-06；沒有可安裝版本。** 目標為《軒轅劍參》Steam HD 4.0.5 的獨立 `.ssmod`。本目錄目前只有設計文件，尚未建立 Lua、動作來源、封包或發布素材；不是 Codex plugin。

使用者要求評估補齊蔡魔王，並先比較「保留 DOMO 造型」與「沿用完整首領造型」；已知新增圖片管線難度高，因此首版以**只引用遊戲內建圖片**為範圍。外觀尚未定案，以下兩路均保留。

## 結論與產品範圍

可以規劃成獨立的「蔡魔王挑戰」MOD，核心包括自己的進入方式、完整可結束的單一首領戰、原版資料缺口修補與診斷。挑戰模式、全魔物靈契是選用整合，不是單獨開戰的必要依賴。

主要不確定性是動作資源登錄，並非顯示名字或建立選單。採用現成完整 ACT 的原型路線有既有首領戰實測可參照；保留 DOMO 造型則須先證明增量 ACT 能載入並完成攻擊／回復／死亡等流程。**「不新增圖片」不能直接推導成「不用驗證新動作」。**

原始崩潰與資料缺口的唯一紀錄見[蔡魔王開戰崩潰評估](../swd3-live-card-battle-mod/BALANCE-AND-SAFETY-AUDIT.md#蔡魔王開戰崩潰評估2026-09-06)，本文件不重新定義其因果結論。所有下列新功能與實作策略均為**專案方案／待驗證**。

ACT 627 包含多位 DOMO 人員動作，不應覆寫整組作為蔡魔王專用動作。優先研究補齊原本未宣告的 ACT 438，或使用經登記的新專用 ACT；只能在確認其他啟用 MOD 未占用時採用。不能修改全量原版 `act.ext` 或替換核心圖像封包。

### 必須驗證的動作契約

新增的魔王／神秘風格候選與比較見下方[既有造型候選](#既有造型候選2026-09-06)；牛魔王只是最初示例，並非已選定外觀。

工作區原版 ACT 101 有 QQ 36／40／48／68，ACT 59 有 QQ 36／40／44／48／49／68，顯示各敵人動作集合不相同。這些只是比較起點，不能假設所有 QQ 的語意或最低集合已完整解明。

| 遊戲行為 | 實作與驗收內容 |
| --- | --- |
| 進場、待機、選取 | 可建立實體並持續待機；位置、尺寸、方向、選取框正常；動作引用的圖像／音效存在。 |
| 普攻 | 出手有且只有預期次數的命中；回到待機，不因缺少攻擊事件而卡住。不能直接複製別隻多段攻擊的命中標記。 |
| 攻擊法術／治療 | 演出、特效、目標、命中／回復事件和結束點一致；療傷不能打向玩家。 |
| 受擊、異常狀態 | 受擊、定身等引擎可到達狀態有安全處理；不要求每種狀態都有新繪圖，但不得索引缺失動作。 |
| 死亡、逃跑、收服、戰敗中止 | 全部結束路徑可返回原場景，沒有卡死、重複結算或殘留角色。 |
| 契靈卡（選用整合） | 卡片反白／資訊、護駕召喚、出招／退場的動作需求另驗，不能由敵方成功代替。 |

研究順序：先查原版 ACT 宣告、`ACT_Append.lua` 與載入方式；隔離驗證少量動作能由獨立 `.ssmod` 註冊。若仍不明，再對相同 exe 指紋追查動作選擇／登錄 native 路徑。完整流程依[引擎研究](../docs/knowledge/engine-research-workflow.md)，不能把 `ACTData` 表存在當成新增 ACT 已支援。

## 角色與技能設計

第一個測試基線保留原資料的 Lv99、HP10000、ATK100、DEF100、SPD40，這是方便對照缺口的測試值，**不是最終首領平衡**。原資料未列 WIS 等若干欄位，必須先讀取實際有效值／預設行為，不能把匯出表的 0 直接當成已定案的數值。

| 行動 | 原版對照 | 首版建議 |
| --- | --- | --- |
| 普通攻擊 | 蔡魔王原始 `AttackEffect=1`。 | 第一個原型只測這個行動；驗證身體動作與效果的命中觸發相符，再開放技能。 |
| 幻光聖劍 | 技能 1676 → 效果 121 → ACT 6044；資料效果點數 120、光屬性。 | 保留原版技能／特效。資料點數不等於最終傷害。 |
| 六芒星斬 | 技能 1668 → 效果 73 → ACT 7013；效果有全體標記、資料點數 80、暗屬性。 | 保留全體攻擊特色；獨立驗證每名目標與多段演出是否重複結算。 |
| 魔氣縱橫 | 技能 1683 → 效果 198 → ACT 6079；技能有 `AddHP=300`。 | 從錯誤 `SP_AttackEffects` 移除，優先按原版既有例子放入 `CR_Skills` 並配置次數、治療動作。以自己的 AI 案例驗證缺血時選取與實際回復。 |

**官方檔內說明，4.0.5 原版基線。** `GameData_BattleCharData.lua:1306` 的康那里士 `ItemTemp[67]` 已使用 `CR_Skills={1683,1683}`；`OnEvent_Battle.lua` 的 `Function.GetBattleCharInitData` 讀取 `CR_Skills`／`CR_SkillsCount`／`CR_Skills_QQ`，`OnEvent_BattleEnemyAI.lua` 治療分支選己方受傷目標，將法術的 `AddHP` 寫入 `RestorHP`。這提供可重用的配置先例，尚未實測蔡魔王套用後的行為。

治療次數降為零後，原版 AI 仍會保留最低候選權重，不能把 `CR_SkillsCount=5` 宣稱為最多只補五次。首版優先沿用原版權重，若產品需要硬性次數／冷卻／低血量階段，才新增限定本角色與戰場的 AI 規則與測試。原始 EXP／Gold 各 1 也只作測試基線；正式獎勵與首領強度必須一起調整，首通獎勵與永久解鎖不列首版必要內容。

## 獨立套件與相容性

建議核心採用**啟用期間的記憶體資料補齊**：保留來源身分 438，於已確認的載入階段補動作與最少必要的戰鬥欄位。這不是修改磁碟上的原版核心資源，也不將補齊資料寫進 `SaveData.ItemTemp`。來源 438 的所有消費者會受影響，需明確記錄欄位所有權；不能只稱「完全不影響其他 MOD」。若最終另建獨立敵人 ID，則來源選單、收服映射、舊卡與存檔都要另作整合，成本較高，不建議首版同時維護兩個蔡魔王。

| 啟用組合 | 預期行為與必要工作 |
| --- | --- |
| 只有本 MOD | 自己的原生選單入口、單隻蔡魔王戰、返回與取消；不依賴 F9 或卡庫函式。不自動發新增契靈卡、不更改原版收妖政策。 |
| 加上挑戰模式 | F9 中既有蔡魔王來源可使用補齊資料；隊伍多隻、各倍率、低難度獎勵、戰敗等沿用挑戰模式自己的契約。若未完成補齊，需由挑戰模式的開戰前防護拒絕，不可假設本 MOD 的選單能保護另一個入口。 |
| 加上全魔物靈契 | 沿用既有 `438 → 10096`，本 MOD 不重新註冊／重編號他人卡片、不再次發卡。需確保卡庫複製到已補齊的 ACT 與技能；收服、卡片反白、護駕與原生新增後交換分別驗收。 |
| 三者同時啟用 | 診斷實際版本、來源資料、派生卡與載入順序；測試不重複發卡／獎勵，不錯誤覆蓋倍率或戰鬥等級。 |

**載入順序是必要工作。** 卡庫在載入期複製來源 438 建立 10096；只在其後修正來源，可能仍留下已註冊的舊卡資料。優先驗證「本 MOD 資料補齊 → 卡庫建立 → 開始遊戲」，不能先承諾任意順序，也不以 GameStart 重建卡庫修補。需要支援雙順序時，應與卡庫協調正式相容介面並驗證 native 註冊時點；必要的小幅卡庫／挑戰模式改動須列為相容性更新，不能假稱只增加新封包便全自動相容。

本 MOD 單獨啟用時，戰鬥基線仍為來源等級；全魔物靈契可能按其規則對戰鬥副本封頂，這是可見的難度差異。測試需分開記錄，不在本 MOD 內加第二套壓等或收妖 bridge。

### 入口與劇情界線

首版建議從可控的平時／物品欄快捷入口呼叫自己的原生選單，提供「介紹、開始、返回」，再啟動專用戰場。鍵位需在實作前檢查原版設定、Steam 快捷鍵與[登記表](../docs/compatibility-registry.md)，本草案不占用新鍵位、namespace、StringDB key 或數字 ID。

原版 `Scene.TALK6976` 含旗標 551／563、山蛇莓 722 與簽名板交換；某些分支提前返回或 `SceneBreak`。因此「在原對話後追加挑戰」並不保證每條路徑都可達。DOMO NPC 對話整合可作後續功能，但不得覆寫簽名任務、改交物品或直接使用會寫 Flag170 的未完成 `BS308`。

首版不必保存完成次數；停用後原版 438 仍是未完成資料，不能宣稱卸載後外部挑戰入口仍安全。已有卡庫 10096 的玩家需先保持卡庫啟用與存檔備份，相關停用規則仍屬卡庫契約。

## 開發階段與交付門檻

| 階段 | 交付內容 | 成本／判定 |
| --- | --- | --- |
| A：動作可行性 | 隔離研究目錄、版本指紋、最少動作封包、進場／普攻／結束證據。路線1驗證新 ACT＋現有 TSW；路線2驗證現成 ACT＋蔡魔王基線。 | 路線1最大不確定性；未通過不投入完整演出。不用退出碼或 mock 代替遊戲結果。 |
| B：完整單隻戰 | 自己的入口、三招技能、基線數值、正常勝敗／逃跑／取消、明確錯誤診斷。 | 中等；在 A 通過後才能合理估算後續工時。 |
| C：產品化與相容 | 強度／獎勵定案、資訊說明、F9 與卡庫的選用整合、版本／載入順序與存檔矩陣。 | 中至高；卡庫註冊與護駕不能省略。 |
| D：發布候選 | 單一 `.ssmod`、自動測試、封裝反解、實機記錄、安裝／停用說明、最後才準備工作坊素材。 | 依前面缺口決定，現階段不承諾日期或已完成比例。 |

預計正式來源分成資料定義、ACT 動作、角色／資料安裝、場景／戰場、相容檢查與文字表；測試分成引用完整性、純規則、mock 與實機。目錄依[專案結構](../docs/knowledge/project-structure-and-metadata.md)，封包流程依[封裝與安裝](../docs/knowledge/packaging-and-installation.md)，不在此複製通用工具指令。

最低驗收包含：完整重啟、不同存檔、單隻全部行動、傷害／治療只結算一次、勝利／戰敗／逃跑／中止、重複開戰、原劇情簽名任務不變；整合版再測五隻混戰、同角色重複、卡庫收服與護駕、全部支援的載入順序、停用／重新啟用。自訂戰場的無 Game Over 行為也要另驗，不能因挑戰模式已有相同設計就視為通過。

所有新 ACT／欄位／圖片／音效引用都做靜態檢查，封裝後逐檔反解比對；若修改 AI，需測低血量、次數耗盡、無有效目標、重入與其他敵人不受影響。實機先完成最小案例再擴大，不為評估而反覆啟動已知會崩潰的原始 438。

## 本次證據與知識歸屬

本次完成原版 Lua／ACT／HD TSW 對照、兩張現成圖片檢視與專案方案；沒有新增遊戲實測。新增 ACT 可用性、完整造型修復及相容順序仍是待驗證，保留本專案；可重跑通用知識待階段 A 的證據形成後，再按根 AGENTS 評估提升。
